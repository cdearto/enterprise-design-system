Data display

Badge & status pill

Small inline indicators that communicate a record's state, lifecycle position, or a numeric count. Status pills carry semantic color; count chips stay neutral. Always inline, never as standalone navigation.

Overview

Two related families share the same chrome but different intent: status pills (.status-pill) communicate workflow position via a 6 px colored dot + label, with a tinted background per state; count chips (.tab-count) are neutral pills that show numeric counts inside tabs or beside labels.

Use cases

  • Workflow status. Inside table rows, card headers, and detail-page chrome to show progress (In Progress · Awaiting Review · Approved).
  • Lifecycle state. On record cards and list items to indicate Draft / Active / Completed / Archived.
  • Tab counts. Beside a tab label to show how many items are in that tab — replaces the need to load the tab to find out.
  • Inline count summaries. Next to a section heading or filter label to show how many items are visible.

Best practices

  • One status per record. A row or card should carry at most one status pill — combining two confuses workflow position.
  • Status pills aren't navigation. Don't make pills clickable links. If a state transition is needed, use a button or dropdown that opens the transition workflow.
  • Don't invent colors. Use the existing variants. If a new state is needed, add a variant to the system rather than inlining a custom color.
  • Count chips stay neutral. Never tint count chips with the same variants as status pills — counts are quantitative, not qualitative.
